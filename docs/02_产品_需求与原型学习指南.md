## 一、一人公司的「全栈」到底包括什么

```
产品（做什么、给谁用、流程对不对）
    ↓
设计（长什么样、怎么点、资产能不能开发）
    ↓
开发（移动端 + Web + 后端 + 部署）
    ↓
验收（P0 闭环 KPI）
```

你已有 **`01_产品_MVP规划与技术方案.md`**，相当于**产品 PRD 初稿**，不必从零写需求。本学习路径是：**把 PRD 变成可开发的原型与视觉**，并用 Cursor 串联。

| 角色 | MVP 你要达到的水平 | 不必追求 |
|------|-------------------|----------|
| 产品 | 流程清晰、状态枚举明确、页面清单完整 | 精美 Axure 动效、商业级用户研究 |
| 设计 | 主色 + 字号 + 关键页效果图 + 切图 | 100% 像素级、完整 Design System |
| 开发 | P0 闭环可演示 | 架构大奖 |

## 二、工具怎么选（Axure / 墨刀 / Figma / 蓝湖 / PS）

### 2.1 产品原型

| 工具 | 特点 | 一人 MVP 建议 |
|------|------|---------------|
| **墨刀** | 国内上手快、移动端原型多、可分享链接 | **首选**：SOS 流程、App 页面跳转 |
| **Axure** | 交互强、学习曲线陡、适合复杂后台 | 运营后台流程复杂时再用 |
| **Figma** | 原型 + 视觉一体、插件生态好 | 已会用 Figma 则可直接画原型 |
| **纸笔 + 拍照** | 零成本 | P0 头脑风暴够用 |

**本项目建议**：用户端 / 救援端用 **墨刀** 或 **Figma** 画 10～15 个核心页；运营后台可用 **Ant Design Pro 页面截图 + 标注** 代替高保真原型。

### 2.2 视觉与交付

| 工具 | 特点 | 一人 MVP 建议 |
|------|------|---------------|
| **Figma** | 行业标准、Dev Mode、组件库 | **首选视觉工具**（与 Cursor 协作最好） |
| **蓝湖** | 国内交付、设计团队协作 | 你无权限时：**让设计导出包**，或自己用 Figma 交付 |
| **Photoshop** | 位图、精修、老素材 | MVP **可不学**；图标用 SVG/Figma 导出 |
| **即时设计** | 国产、类 Figma | Figma 访问困难时的替代 |

**本项目建议**：**Figma 画 UI + 导出切图/Dev Mode 标注**；开发按 [移动端设计交接](./03_设计_移动端设计交接指南.md) 建 Token。

### 2.3 推荐组合（只学一套，减少切换）

| 组合 | 适合 |
|------|------|
| **墨刀（原型）+ Figma（视觉）** | 产品思维弱、要先「点得着」 |
| **Figma 全流程** | 愿一个工具搞定原型 + UI |
| **MVP 极速** | 墨刀低保真 + Ant Design Pro 默认 UI（Web）+ Flutter Material（App） |

## 三、系统学习路线（4 周，边做本项目）

与 [MVP 分阶段任务](./01_产品_MVP规划与技术方案.md#六分阶段开发任务清单) 对齐，**每周都有可交付物**。

### 第 1 周：产品思维 + 流程固化

| 学什么 | 怎么做（本项目） | 产出物 |
|--------|------------------|--------|
| 用户故事 | 从 MVP P0 闭环拆 5 条故事 | `docs/user_stories.md` |
| 页面清单 | 对照附录 B P0 功能 | `docs/page_inventory.md` |
| 状态机 | SOS 状态枚举与跳转 | 更新 mvp_plan 或单独流程图 |
| 墨刀/Figma 低保真 | 只画 SOS：首页→长按→确认→状态页 | 可分享原型链接 |

**Cursor 用法**：把 `01_产品_MVP规划与技术方案.md` 发给 Agent，要求生成 `user_stories.md` 和 SOS 流程 Mermaid。

**用户故事模板**：

```
作为【普通用户】，我想【长按 SOS 3 秒】，以便【在遇险时触发救援】。
验收：平台 3 秒内收到事件；App 显示 CREATED 状态。
```

---

### 第 2 周：原型交互（墨刀或 Figma）

| 学什么 | 怎么做 | 产出物 |
|--------|--------|--------|
| 信息架构 | Tab 结构：Home / Devices / Profile | 原型 5～8 页 |
| 关键交互 | 长按、弹窗、加载、错误态 | 墨刀交互事件 |
| 运营后台 | SOS 列表、详情、地图占位 | 可先用 Pro 模板截图标注 |

**页面优先级（与开发一致）**：

1. 登录 / 注册  
2. 首页 + SOS 按钮  
3. SOS 确认弹窗  
4. SOS 状态 / 时间线  
5. 设备列表 / 绑定  
6. （Web）SOS 中心 + 地图  

**不必画**：所有设置子页、空状态全集、深色模式（P2）。

---

### 第 3 周：视觉设计（Figma）

| 学什么 | 怎么做 | 产出物 |
|--------|--------|--------|
| 色彩与字体 | 1 主色 + 中性色 + 错误色 | Figma Variables 或样式 |
| 组件 | 按钮、输入框、卡片、SOS 主按钮 | Components 页 |
| 关键页高保真 | 第 2 周原型对应页 | 375×812 画板 |
| 开发标注 | Dev Mode 或导出标注 PDF | 色值/间距表 |

**与开发打通**：按 [03_设计_移动端设计交接指南.md](./03_设计_移动端设计交接指南.md) 导出开发包（切图 + 色值表 + 全屏 PNG）。

**英文界面**：文案直接写 en-US，与 API 状态一致（`CREATED`、`ON_THE_WAY`…）。

---

### 第 4 周：设计 → 开发贯通 + 验收

| 学什么 | 怎么做 | 产出物 |
|--------|--------|--------|
| Design Token | `AppColors`、`AppSpacing` | `rescue_mobile_ui` |
| 截图叠图 | 关键页对齐 | 真机与效果图肉眼一致 |
| Web 对齐 | Ant Design Pro 主题 token | `rescue_ops_web` theme |
| 产品验收 | 走通 P0 闭环 | 检查表打勾 |

## 四、产品 / 设计 / 开发「打通」流水线

```
01_产品_MVP规划与技术方案.md     ← 产品真相（需求、状态、表结构）
        ↓
docs/user_stories.md            ← Cursor 生成，你审核
        ↓
墨刀 / Figma 原型               ← 流程与页面
        ↓
Figma 高保真 + 开发包           ← 色值、切图、PNG（见设计交接 doc）
        ↓
docs/openapi.yaml               ← 前后端契约（Cursor 生成）
        ↓
Flutter / React / Spring Boot   ← 开发实现
        ↓
P0 验收 KPI                     ← mvp_plan §八
```

**单一事实来源**：功能范围以 **`01_产品_MVP规划与技术方案.md`** 为准；原型/视觉与 PRD 冲突时，**先改 PRD 再改设计再改代码**。

## 六、全部用 Cursor：怎么分工

你已决定 **只用 Cursor**，可把原来三 IDE 职责合并为 **不同 Chat / Rules / 模式**：

| 虚拟角色 | Cursor 中怎么做 | 典型任务 |
|----------|-----------------|----------|
| 产品 | 新 Chat + `@01_产品_MVP规划与技术方案.md`，只讨论需求与流程 | 用户故事、页面清单、验收标准 |
| 设计 | 新 Chat + 上传 Figma 导出 PNG / 贴色值表 | 生成 Theme、Widget 骨架、文案 en-US |
| 后端 | Chat + `@rescue_platform_api` + Spring Boot 学习 doc | API、migrations、MQTT |
| 移动端 | Chat + `@rescue_mobile_suite` + 设计交接 doc | SOS 页、Token |
| Web | Chat + `@rescue_ops_web` | Ant Design Pro 页面 |
| 运维 | Chat + `@rescue_platform_infra` + 终端 | docker compose、SSH 部署脚本 |

### 6.1 建议的 `.cursor/rules` 分文件

在 `~/rescue_platform/` 或各仓库放规则（可选）：

```
.cursor/rules/product.mdc    → 只改 docs/，输出用户故事、流程图
.cursor/rules/design.mdc     → 关注 rescue_mobile_ui、theme，引用设计交接 doc
.cursor/rules/backend.mdc    → Spring Boot 或 Go，引用对应 backend learning doc
```

### 6.2 Cursor 产品向提示词模板

```
阅读 01_产品_MVP规划与技术方案.md 附录 B，
列出 rescue_user_app P0 页面清单表格（页面名、入口、主要操作、对应 API）。
```

### 6.3 Cursor 设计向提示词模板

```
附件是 SOS 首页 Figma 导出 PNG 和色值表：
主色 #E53935，正文 #212121，间距 8/16/24。
在 packages/rescue_mobile_ui 生成 AppColors、AppTextStyles、SosButton widget，
界面文案 en-US。
```

### 6.4 与「三 IDE 方案」的关系

任务拆分见 [08_开发_Cursor协作指南.md](./08_开发_Cursor协作指南.md)；工具统一 Cursor 时，用**新会话 + @ 文档**区分产品/设计/开发。
