```
开发完成模块 → 【本文：对应层级测试】→ 通过 → 下一模块 / 上线
```

## 二、测试分层

| 层级 | 范围 | 工具建议 | 负责人（一人公司） |
|------|------|----------|-------------------|
| 单元测试 | Service、工具函数 | JUnit / `go test` | Cursor 生成，你跑 |
| 接口测试 | REST API | Bruno、Postman、curl | 手工 + 集合导出 |
| MQTT 测试 | 设备 SOS 上报 | MQTTX、mosquitto_pub | 手工 + 脚本 |

| WebSocket | 运营端推送 | wscat、前端 DevTools | 手工 |
| E2E | 全闭环 | 手工走查 + 后续 Maestro/Playwright | 你 |
| 压测 | SOS 高峰 | k6、Gatling（第五阶段） | 09 环境 |

## 三、P0 验收 KPI（必测）

| 指标 | 目标 | 测法 |
|------|------|------|
| SOS 送达率 | > 99.9% | 连续 N 次 MQTT 发布，统计入库成功 |
| SOS 平台接收延迟 | < 3 秒 | Topic 发布到 DB 可查时间差 |
| 后台地图出现 | < 1 秒（01 二阶段验收） | WebSocket 收到 → 地图打点 |
| WebSocket 推送延迟 | < 1 秒 | 服务端时间戳对比 |
| GPS 精度 | < 10 米（条件允许） | 对比实测坐标 |
| 调度员响应 | < 60 秒 | 人工计时（试点） |

## 四、后端测试

### 4.1 接口用例（示例）

| # | 场景 | 步骤 | 预期 |
|---|------|------|------|
| A1 | 创建 SOS | POST `/api/v1/sos` + Token | 201，`status=CREATED` |
| A2 | 查询 SOS | GET `/api/v1/sos/{id}` | 200，字段完整 |
| A3 | 状态更新 | PATCH status → `CONFIRMED` | 200，Redis 同步 |
| A4 | 未授权 | 无 Token 访问 | 401 |

### 4.2 MQTT 用例

| # | 场景 | 步骤 | 预期 |
|---|------|------|------|
| M1 | SOS 上报 | 发布 `rescue/iot/{id}/sos` | `sos_events` 有记录 |
| M2 | 重复上报 | 相同 idempotency key | 不重复插入 |
| M3 | 高峰 | GPS 与 SOS 同时 | SOS 先处理（01 原则） |

### 4.3 命令示例

```bash
# 健康检查
curl -s http://localhost:8080/actuator/health

# 创建 SOS（示例 body 以 openapi 为准）
curl -X POST http://localhost:8080/api/v1/sos \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"lat":37.77,"lng":-122.42,"source":"APP"}'
```

## 六、E2E 闭环用例（P0 终验）

**主路径**（01 P0 闭环）：

| 步骤 | 操作 | 验证 |
|------|------|------|
| 1 | 设备/模拟器发 SOS | 3 秒内 DB 有记录 |
| 2 | 打开运营 Web SOS 中心 | 列表出现新事件 |
| 3 | 地图 | 点位正确 |
| 4 | 调度派单 | 工单状态流转 |
| 5 | 救援 App 接单 | worker 端状态更新 |
| 6 | 用户 App | 跟踪页显示进度 |
| 7 | 完成 | `COMPLETED` 归档 |

**记录**：每步截图 + 时间戳，作为试点验收附件。
