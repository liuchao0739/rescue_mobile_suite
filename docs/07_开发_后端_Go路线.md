## 一、为什么本项目推荐 Go

| 场景 | Go 优势 |
|------|---------|
| `rescue_mqtt_worker` 高并发消费 |  goroutine 轻量，适合大量设备连接 |
| 多进程部署（api / mqtt / ws / notify） | 单二进制，部署简单 |
| 与文档默认骨架一致 | 仓库 `cmd/`、`internal/` 已按 Go 规划 |

**若你 Spring Boot 很熟、工期紧**：可先用 [Spring Boot 路线](./06_开发_后端_SpringBoot路线.md) 跑通 P0，再将热点模块用 Go 重写。

## 二、Spring Boot → Go 概念对照

| Spring Boot / Java | Go 生态（本项目推荐） |
|--------------------|----------------------|
| `@RestController` | Gin / Fiber `router.GET/POST` |
| `@Service` | `internal/service` 包函数或 struct |
| Spring Data JPA | GORM 或 sqlx + 手写 SQL |
| MyBatis XML | sqlx 或 go-sqlbuilder |
| `application.yml` | viper / env + `config.yaml` |
| Spring Security JWT | `golang-jwt/jwt` + 中间件 |
| Spring Data Redis | `go-redis/redis/v9` |
| Spring Integration MQTT | `eclipse/paho.mqtt.golang` |
| `@Async` / RabbitMQ | goroutine + channel 或 `amqp091-go` |
| Actuator `/health` | 自定义 `/health` 或 `heptiolabs/healthcheck` |
| Flyway | `golang-migrate/migrate` 或 goose |
| 多 Module 微服务 | 同仓多 `cmd/xxx/main.go` |

### 第 4 周：Redis + mqtt_worker

| 学习目标 | 在本项目中的产出 |
|----------|------------------|
| go-redis | 设备在线、GPS、SOS 状态缓存 |
| paho.mqtt.golang | `cmd/mqtt_worker` 订阅 SOS Topic |
| 优雅退出 | signal.Notify + context cancel |

**mqtt_worker 核心逻辑**：

```
订阅 rescue/iot/+/sos
  → 解析 JSON
  → 幂等检查（device_id + ts）
  → INSERT sos_events
  → SET redis rescue:sos:{id}:status
  → （可选）发 channel 通知 ws_server
```

**OpenCode 并行**：在 `rescue_platform_infra` 写 SOS 联调 shell 脚本 + `go test` 集成测试。

## 八、服务器部署（SSH）

与 Spring Boot 路线相同：**Cursor 写脚本，你在终端 SSH 执行**。

```bash
# 构建 Linux 二进制（在 Mac 上交叉编译）
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o bin/api ./cmd/api
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o bin/mqtt_worker ./cmd/mqtt_worker

# 服务器上
scp bin/api bin/mqtt_worker deploy@server:~/rescue/
ssh deploy@server
cd ~/rescue && docker compose -f docker-compose.prod.yml up -d
```

**Go 部署优势**：单文件二进制，无需在服务器装 JRE。

| 选择 | 建议 |
