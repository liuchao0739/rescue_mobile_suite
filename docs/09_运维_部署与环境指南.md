## 一、运维在全流程中的位置

```
产品 / 设计
      ↓
开发启动前 → 【09 本地环境】→ 后端 / 前端联调
      ↓
测试通过   → 【09 SSH 上云】→ staging / prod
      ↓
试点上线   → 监控、备份、告警（01 第四、五阶段）
```

**原则**：开发**先本地 compose**，**后**云服务器；密钥不进 Git。

## 三、本地开发环境（P0 必做）

### 3.1 组件清单

| 组件 | 镜像/版本 | 端口（示例） | 用途 |
|------|-----------|--------------|------|
| PostgreSQL 15 | postgres:15 | 5432 | 业务库 `rescue_platform_db` |
| PostGIS | 可选扩展 | — | 地图/GIS |
| Redis 7 | redis:7 | 6379 | 缓存、SOS 实时状态 |
| EMQX 5 | emqx:5 | 1883 / 8883 | MQTT Broker |
| RabbitMQ | rabbitmq:3（可选） | 5672 | 异步削峰 |
| MinIO | minio（可选） | 9000 | 对象存储 dev |

### 3.2 启动步骤

```bash
cd ~/rescue_platform/rescue_platform_infra
docker compose up -d
docker compose ps
```

### 3.3 健康检查

```bash
# PostgreSQL
docker compose exec postgres pg_isready

# Redis
docker compose exec redis redis-cli ping

# EMQX Dashboard（若开启）
open http://localhost:18083
```

### 3.4 应用连接（dev）

```env
DATABASE_URL=postgres://rescue:rescue@localhost:5432/rescue_platform_db
REDIS_ADDR=localhost:6379
MQTT_BROKER_URL=tcp://localhost:1883
```

后端在 `rescue_platform_api` 使用 `application-dev.yml` 或 `.env`（**加入 .gitignore**）。

## 四、Cursor 与 SSH

| 任务 | 谁执行 |
|------|--------|
| 编写 `docker-compose.yml`、Dockerfile、Nginx 配置 | **Cursor** 生成，人 review |
| `docker compose up`、查看 logs | 本机终端 或 Cursor 终端 |
| `ssh deploy@服务器` | **你**在终端执行 |
| 排查启动失败 | 日志贴回 Cursor |

```bash
ssh deploy@your-server-ip
cd ~/rescue && docker compose -f docker-compose.prod.yml up -d
curl -s http://localhost:8080/actuator/health   # Spring
curl -s http://localhost:8080/health              # Go
```

## 五、云服务器部署清单（staging）

### 5.1 服务器建议

| 项目 | MVP 建议 |
|------|----------|
| 规格 | 2 核 4G 起 |
| 系统 | Ubuntu 22.04 LTS |
| 开放端口 | 22、80、443；（MQTT 8883 按需） |

### 5.2 首次初始化

```bash
sudo apt update && sudo apt install -y docker.io docker-compose-plugin
sudo usermod -aG docker $USER
# 重新登录后
mkdir -p ~/rescue && cd ~/rescue
```

### 5.3 部署文件（由 Cursor 生成）

| 文件 | 说明 |
|------|------|
| `docker-compose.prod.yml` | PG + Redis + EMQX + API 镜像 |
| `.env.prod` | 密钥，仅服务器本地 |
| `nginx.conf` | 反向代理 + HTTPS（certbot） |

### 5.4 发布流程

```
本地测试通过（10 测试文档）
    → 构建镜像 / 二进制
    → scp 或 git pull 到服务器
    → docker compose pull && up -d
    → 健康检查 + 冒烟 SOS
```

## 七、备份与安全

| 项 | 建议 |
|----|------|
| PostgreSQL | 每日 `pg_dump`，保留 7 天 |
| `.env` | 不进 Git；服务器权限 `600` |
| EMQX | 设备 TLS；生产关闭匿名 |
| SSH | 密钥登录，禁用密码 |

| MVP 阶段 | 运维任务 |

## 九、检查清单

**本地**

- [ ] `docker compose up -d` 全部 healthy
- [ ] MQTTX 能连 EMQX 并发布 SOS Topic
- [ ] API 能连 PG、Redis

**staging**

- [ ] SSH 可登录
- [ ] HTTPS 证书有效
- [ ] `/health` 返回 UP
- [ ] 外网可访问 SOS API（鉴权开启）
